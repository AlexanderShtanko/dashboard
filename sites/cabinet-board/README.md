# Кабинет

Рабочая основа личной доски: свободное размещение, размер и поворот карточек, вложенные папки и отдельные экраны. JavaScript ES modules, без сборки и внешних runtime-зависимостей. Системная типографика: San Francisco на Apple, Segoe UI на Windows; внешние шрифты не загружаются.

## Запуск

В Windows дважды нажать `start-cabinet.bat` в папке проекта. Файл проверит наличие Node.js, запустит сервер и откроет кабинет в браузере после готовности сервера. Устанавливать npm-зависимости не требуется. Оставлять окно терминала открытым во время работы; для остановки нажать Ctrl+C или закрыть окно. Если порт 4173 занят, появится понятное сообщение.

Данные автономного `cabinet-preview.html` и локального сайта хранятся отдельно. Чтобы перенести доску из автономной версии, экспортировать её там и импортировать на локальном сайте.

```sh
npm run dev
npm test
```

Локальный адрес: http://127.0.0.1:4173. Открывать через HTTP: ES modules не рассчитаны на запуск через `file://`.

Для автономного просмотра: `npm run preview:build`. Полученный `cabinet-preview.html` можно открыть прямо с диска; он содержит все модули приложения. Сохранять рабочие данные надёжнее в HTTP-версии: поведение localStorage для file-адресов зависит от браузера. Автономная копия не заменяет исходные модули и после изменений пересоздаётся той же командой.

## Расширение для Chrome

Готовая папка `chrome-extension` содержит «Кабинет» целиком и работает без локального сервера. Если папки нет или изменился исходный код, соберите её командой `npm run extension:build` из папки проекта.

1. В настольном Chrome откройте `chrome://extensions/` и включите **Режим разработчика**.
2. Нажмите **Загрузить распакованное расширение** и выберите папку `chrome-extension` с файлом `manifest.json`. Новую вкладку можно открыть через **Ctrl + T**.
3. Чтобы доска появлялась при запуске, откройте `chrome://settings/onStartup` и выберите **Новая вкладка**. Chrome показывает одну страницу новой вкладки, поэтому при конфликте отключите другое расширение, которое её заменяет.

Расширение хранит доску и PIN в `chrome.storage.local` текущего профиля Chrome (разрешения `storage` и `unlimitedStorage`). При первом запуске версии 0.1.3 доска и PIN, сохранённые ранее расширением в `localStorage`, переносятся автоматически; старая копия в `localStorage` остаётся как резервная. Чтобы перенести доску из локальной версии, выберите в ней **Меню → Экспорт доски**, а в новой вкладке выберите **Меню → Импорт доски** и укажите сохранённый JSON-файл. Для обновления пересоберите расширение в той же папке и нажмите **Обновить** на его карточке в `chrome://extensions/`; сохраняйте экспорт доски перед удалением расширения.

### Синхронизация между компьютерами

Начиная с версии 0.2.0 доска синхронизируется через `chrome.storage.sync`: на всех компьютерах, где Chrome вошёл в один аккаунт Google и включена синхронизация (в том числе раздел «Расширения»). Главная копия по-прежнему хранится локально в `chrome.storage.local`, синхронизация — её реплика.

- Фиксированный `key` в манифесте даёт расширению один и тот же ID (`clodoojibbnlmboeoabhfpaiflafdahh`) на любом компьютере и из любой папки. Без этого Chrome не связал бы данные распакованных расширений.
- С `chrome.storage.sync` работает только фоновый service worker (`background.js`, логика в `core/sync.js`), поэтому открытые вкладки не мешают друг другу. Изменения отправляются через ~3 секунды после сохранения и не чаще одного раза в 10 секунд — это укладывается в лимиты Chrome (120 записей в минуту, 1800 в час).
- Доска сжимается gzip и делится на части по 7,6 КБ (лимит Chrome — 8 КБ на запись). Синхронизируется доска до ~45 КБ после сжатия — обычно это сотни килобайт текста. Если доска больше, она продолжает сохраняться на этом компьютере, а в меню появляется «Сохранено только на этом компьютере» с объяснением.
- Конфликты: если на двух компьютерах изменили разные виджеты, изменения объединяются. Если один и тот же виджет изменили на обоих, остаётся версия этого компьютера, а версия с другого добавляется рядом копией «… — с другого компьютера». Удаление на одном компьютере удаляет виджет и на другом, если его там не меняли.
- PIN синхронизируется как солёный хеш PBKDF2 (сам PIN не хранится), действует последнее изменение.
- Открытые вкладки подхватывают изменения сразу, без перезагрузки. Кеш курсов валют не синхронизируется.

### Google Диск и телефон

Начиная с версии 0.3.0 доску можно синхронизировать через Google Диск, а на телефоне открывать веб-версию (PWA) из папки `dist/`, размещённой на HTTPS-хостинге.

- Доска и запись PIN хранятся в одном файле `cabinet-board.json` в скрытой папке приложения на Диске (`appDataFolder`, доступ `drive.appdata`). Остальные файлы Диска приложению не видны. Лимита в 45 КБ здесь нет.
- Вход без сервера и без сторонних скриптов: в расширении через `chrome.identity.launchWebAuthFlow`, на сайте — переходом на страницу Google и обратно. Токен живёт час; расширение обновляет его само, сайт — при следующем открытии.
- Расширение синхронизирует Диск в фоне (`background.js`): после изменений, раз в минуту и при открытии новой вкладки. Веб-версия синхронизирует прямо в странице: после изменений, при возвращении на вкладку и раз в минуту.
- Слияние и конфликты такие же, как у синхронизации Chrome (`core/sync.js`, общий движок). Локальная копия остаётся главной и работает офлайн.
- Настройка: OAuth-клиент типа «Web application» в Google Cloud с включённым Google Drive API. Его Client ID указывается в `dist/config.js`; пока он пустой, раздел «Google Диск» в меню скрыт. Redirect URIs клиента: `https://clodoojibbnlmboeoabhfpaiflafdahh.chromiumapp.org/`, адрес сайта (со слешем в конце) и `http://127.0.0.1:4173/` для локальной проверки.
- PWA: `manifest.webmanifest`, иконки в `icons/`, офлайн-кеш `service-worker.js` (новая версия сайта применяется при следующем запуске).

[Установка расширения из папки](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked) · [Настройки запуска Chrome](https://support.google.com/chrome/answer/95314?hl=ru)

## Что работает

- Стиль ChromeOS / Material You: шрифт Google Sans (лежит в dist/fonts, лицензия OFL), тональные цвета Material 3, мягкие обои, плоские карточки с лёгкой тенью, кнопки-«таблетки», полупрозрачная полка с кнопками внизу по центру и тёмный снекбар. Системная настройка уменьшения движения учитывается.
- На доске карточка двигается сразу за мышью. Короткий клик открывает содержимое. На сенсорном экране удержите карточку и ведите её, не отпуская; поле двигается одним пальцем, масштаб меняется двумя. Размер и поворот доступны через ⋯ → «Размер и поворот».
- Пустая доска и пустая папка показывают стеклянное приглашение и работающую кнопку добавления первой карточки.

- Доска занимает всё окно без боковой и верхней панелей. Плавающая панель кнопок: меню, добавление, «показать все карточки» и (на компьютере) полноэкранный режим. На компьютере она справа вверху, на телефоне — внизу по центру, под большим пальцем. Меню разбито на разделы: «Доски» (папки), «Вид» (доска или список, масштаб, отмена), «Защита» (PIN), «Данные» (состояние сохранения, Google Диск, копия в файл). Внутри папки появляется компактный путь назад.
- Меню карточки ⋯: открыть, переименовать, размер и поворот, дублировать, переместить в папку, порядок, PIN, удалить. Удаление срабатывает сразу, в плашке внизу есть «Отменить». В списке удержание карточки открывает то же меню.
- На телефоне (до 600 px) меню и каталог выезжают снизу, формы открываются у верхнего края, чтобы клавиатура их не закрывала. На сенсорных экранах кнопки не меньше 40–44 px, а поля ввода — 16 px, чтобы iOS не увеличивал страницу. Правила лежат в конце `dist/style.css` (блоки «Controls», «Touch», «Phone»).
- Кнопка fullscreen включает полноэкранный режим браузера, повторное нажатие или Esc возвращает обычный вид. Если встроенный браузер запрещает Fullscreen API, приложение показывает подсказку для открытия в отдельном браузере. Размер и положение виджетов при этом не меняются.

- Заметки с автосохранением текста; задачи с добавлением, редактированием и выполнением; коллекции ссылок; таймер фокуса; вложенные папки.
- «Накопления» загружают справочные курсы [Frankfurter](https://frankfurter.dev/) автоматически. Для итога за прошлую дату используются курсы на эту дату, а для будущей — на сегодня. Запрос содержит только валюту итога и дату. Последние ответы кешируются отдельно от доски. Если нужный курс не получен, можно заполнить его вручную в разделе «Валюта и курсы».
- На доске режим «Расставить»: перемещение за заголовок, размер за углы, поворот за верхний круг. Shift фиксирует пропорции при resize и шаг 15° при повороте. Стрелки работают для выделенного заголовка или маркера.
- Перенос в папки через параметры или перетаскиванием заголовка на папку. Папки могут содержать папки, циклы запрещены.
- Вынести карточку из папки: ⋯ → «Вынести на доску» (в списке на телефоне то же меню открывает удержание карточки); правый клик или удержание плитки на карточке папки; в режиме «Доска» внутри папки карточку можно бросить на путь вверху («Моя доска» или любая папка выше). Карточка ложится рядом с папкой, в плашке есть «Отменить». Плитку можно и просто перетащить с карточки папки на доску (на телефоне: удержать и потянуть), она ляжет там, где её отпустили.
- Удаление папки поднимает содержимое на родительскую доску. Дублирование папки создаёт независимые копии всего дерева.
- Undo (40 последних операций в текущей вкладке); JSON export/import с валидацией. Импорт требует подтверждения замены.
- На телефоне по умолчанию используется список карточек; порядок в нём меняется через ⋯ → «Выше/Ниже в списке». На любом размере экрана можно переключаться между списком и доской.
- URL маршруты `#/board`, `#/folder/<id>`, `#/widget/<id>`; Back возвращает предыдущий экран. Камера сохраняется при переходах между папками в текущей вкладке.

## Границы текущей версии

В меню доски можно задать общий PIN из 4–12 цифр. Чтобы скрыть отдельный виджет или папку с содержимым, выберите **⋯ → Защитить PIN-кодом**. После перезагрузки страницы защищённые карточки закрываются снова. Открытые карточки также можно закрыть вручную через меню.

PIN действует в текущем браузере и на текущем адресе доски. Защита скрывает карточки в интерфейсе. Локальные данные и экспортированные файлы хранятся без шифрования. При переносе защищённых карточек используется PIN той доски, куда их импортировали.

Данные хранятся под ключом `cabinet-board:workspace:v1`: в расширении — в `chrome.storage.local`, на локальном сайте и в автономной копии — в `localStorage`. Выбор делает `core/storage.js`; он загружает данные один раз при старте и даёт приложению синхронный интерфейс `getItem/setItem`, запись в `chrome.storage` идёт в фоне, ошибки записи показываются как «Не сохранено». Кеш курсов валют остаётся в `localStorage`. Это локальное сохранение в конкретном браузере и на конкретном адресе сайта, не облачная синхронизация. Доску можно перенести JSON-файлом. Публикация кода не загружает пользовательские записи на сервер. Приватный доступ Sites и локальное хранение — разные механизмы.

При заполненном/запрещённом хранилище приложение сообщает «Не сохранено» и позволяет экспортировать текущую копию. При повреждении сохранённой доски исходная строка не перезаписывается, экспорт выдаёт исходную копию для восстановления. Одновременное редактирование в разных вкладках не объединяется: показывается предупреждение, требуется экспорт/перезагрузка. Полноценный sync-адаптер — отдельный следующий этап.

## Добавить тип виджета

Создать `dist/widgets/my-widget.js`, экспортировать определение и зарегистрировать его в `dist/widgets/index.js`. Оболочка, каталог и маршруты автоматически используют реестр. Изменение `app.js` не требуется.

```js
import {el} from '../core/dom.js';
export const myWidget = {
  type: 'my-widget',             // стабильный уникальный ASCII id
  version: 1,                   // версия схемы данных этого типа
  title: 'Мой виджет',
  description: 'Описание для каталога',
  icon: 'note',                 // note, tasks, links, folder, focus
  tone: 'paper',                // paper, white, sage, sand
  size: {w: 300, h: 240},
  minSize: {w: 220, h: 170},
  createData: () => ({text: ''}),
  validate: data => typeof data.text === 'string',
  renderCard(ctx) {
    return el('button', {onClick: ctx.open}, ctx.node.data.text || 'Открыть');
  },
  renderScreen(ctx) {           // необязательный отдельный экран
    return el('p', {}, ctx.node.data.text);
  }
};
```

Затем импортировать `myWidget` и добавить его в список регистрации. Код модулей доверенный и входит в поставку приложения: сторонние исполняемые плагины не загружаются из JSON.

### Контекст модуля

`node`: снимок экземпляра при рендере. `latest()`: актуальная запись; использовать в обработчиках. `update(data)`: заменить данные текущего экземпляра; shell сохраняет и валидирует. `open()`: перейти на экран экземпляра. `children(parentId)`: прямые дочерние записи. `registry`: метаданные типов. `feedback(text)`: короткое сообщение статуса.

Рендерер возвращает DOM-элемент или `{element, dispose}`. `dispose` вызывается перед удалением карточки/экрана, чтобы остановить таймеры, сохранить отложенный ввод и снять подписки. В отдельном экране изменения данных не пересоздают DOM: модуль отвечает за собственные обновления и положение курсора. Сохранение одного виджета не изменяет другие.

### Хранение и версии

Запись: `{id, type, version, parentId, title, data, layout: {x, y, w, h, rotation}}`. `x,y` — центр карточки в координатах родительской доски, угол в градусах. Дочерние виджеты определяются по `parentId`, данные не вкладываются друг в друга. Папка — встроенный контейнер `folder`; её содержимое открывается общей оболочкой доски.

При изменении данных увеличивать `version` и добавлять `migrations: {1: old => newData}` для перехода 1→2 и так далее. Неизвестный тип сохраняет исходные данные и отображается заглушкой. Версии данных новее модуля отклоняются без перезаписи сохранённой доски.

`core/store.js` — независимая от UI модель и адаптер сохранения. `core/geometry.js` — преобразования канваса. `core/registry.js` — контракт и миграции. `widgets/` — реализации. `app.js` — общая оболочка, маршруты и жесты. Тесты проверяют дерево папок, миграции, валидацию импорта, сохранение и resize повёрнутых объектов.

Статическая публикация Sites использует `dist/` и `.openai/hosting.json`.
