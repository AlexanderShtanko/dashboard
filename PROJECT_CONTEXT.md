# «Кабинет» — контекст для продолжения разработки

«Кабинет» — персональная доска для компьютера и телефона. Пользователь открывает её, чтобы увидеть дела, отметить ежедневное действие, записать мысль или проверить накопления и вернуться к своей задаче. Главный принцип интерфейса — на доске виден короткий ответ, а подробности и настройки открываются по запросу.

**Рабочее приложение находится в [sites/cabinet-board](sites/cabinet-board/). Его исходники лежат прямо в `dist/`.** Здесь и далее пути без префикса указаны относительно `sites/cabinet-board/`. Соседний каталог `sites/quiet-study/` содержит ранний визуальный прототип. Снимки интерфейса в проекте показывают разные этапы дизайна. Актуальный вид можно увидеть при локальном запуске.

## Запуск за минуту

Для разработки нужен Node.js с npm. Проект написан на JavaScript с ES-модулями, HTML и CSS. Устанавливать пакеты перед запуском не требуется.

```powershell
# Из корня репозитория
cd sites/cabinet-board
npm run dev
```

Откройте `http://127.0.0.1:4173/`. Сервер отдаёт файлы из `dist/` напрямую. После правки достаточно обновить страницу. В Windows можно запустить [start-cabinet.bat](sites/cabinet-board/start-cabinet.bat) двойным щелчком.

| Команда из каталога приложения | Что делает |
| --- | --- |
| `npm test` | Запускает тесты Node.js для доски, жестов, PIN, ежедневных действий и накоплений. |
| `npm run extension:build` | Собирает расширение из тех же исходников в `chrome-extension/`. В `chrome://extensions` включите режим разработчика и загрузите эту папку как распакованное расширение. После следующих сборок нажмите «Обновить» у расширения и откройте новую вкладку. |
| `npm run preview:build` | Собирает автономный файл `cabinet-preview.html`. Сборщик рассчитан на используемые в проекте относительные именованные импорты и экспорты. |

Расширение заменяет страницу новой вкладки Chrome. Чтобы видеть доску и при запуске браузера, в настройках запуска Chrome выберите открытие новой вкладки. Локальный сайт и расширение используют разные хранилища. Перенести доску между ними можно экспортом и импортом JSON.

## Как устроен пользовательский опыт

Доска занимает весь экран. Наверху остаются добавление, полноэкранный режим и меню. На компьютере карточки свободно двигаются мышью за тело карточки. На сенсорном экране удержание позволяет начать перемещение тем же пальцем. В режиме редактирования доступны изменение размера и поворот. При ширине до 700 пикселей включительно начальным представлением служит список. Папка открывает вложенную доску, а заголовок обычного виджета с подробностями ведёт на его экран.

Текущее визуальное направление — современный скевоморфизм: матовая бумага, мягкие тени, объёмные кнопки, карточки без явного контура. При изменении интерфейса сохраняйте читаемую иерархию, доступ к меню «⋯» и различие между нажатием на элемент управления и перетаскиванием карточки. Форма ввода, история и редкие настройки обычно уместнее на экране виджета.

| Тип | Что уже реализовано |
| --- | --- |
| `note` | Текст заметки на карточке и редактор с автосохранением. |
| `tasks` | Список задач, отметки выполнения и прогресс. |
| `daily` | Повторяющиеся действия. На карточке видны последние семь дней, в подробностях можно менять отметки задним числом и смотреть историю за всё время. Отметки привязаны к локальной календарной дате. |
| `folder` | Вложенная доска с карточками и другими папками. |
| `links` | Ярлыки как на новой вкладке Chrome: круглые плитки с иконкой сайта (в расширении — из локального кеша Chrome через разрешение `favicon`, на сайте — через сервис Google), буква-аватар, если иконки нет. Меню ⋯ при наведении (изменить, удалить), диалог добавления, перетаскивание мышью для порядка, Alt+←/→ с клавиатуры. Формат данных прежний, v1. Чистые функции — в `links-data.js`. Переход открывается в той же вкладке. |
| `focus` | Таймер для работы над задачей. |
| `savings` | Счета с названием, цветом, валютой и остатками по датам. Для итога берётся последний известный остаток каждого счёта на выбранную дату. Пересчёт в общую валюту учитывает онлайн-курсы Frankfurter, кеш и ручные курсы. |

Новости из личного агрегатора и погода обсуждались как направления развития. Синхронизация между устройствами реализована через `chrome.storage.sync` и Google Диск (см. «Данные и приватность»); собственного сервера и аккаунтов нет. Веб-версия из `dist/` устанавливается на телефон как PWA.

## Данные и приватность

Доска сохраняется под ключом `cabinet-board:workspace:v1`: в расширении в `chrome.storage.local`, на сайте в `localStorage`. Локальная копия главная; синхронизация (Chrome и Google Диск) — её реплики, см. README приложения. Формат верхнего уровня — `{ schemaVersion: 1, nodes: [...] }`. Узлы хранятся в плоском массиве. Например, заметка на корневой доске выглядит так:

```json
{
  "id": "example-note",
  "type": "note",
  "version": 1,
  "parentId": null,
  "title": "На сегодня",
  "data": { "body": "Закончить черновик" },
  "layout": { "x": 190, "y": 170, "w": 290, "h": 250, "rotation": 0 }
}
```

- `parentId` содержит идентификатор папки или `null` для корня. Координаты задают центр карточки на доске родителя, поворот хранится в градусах. Циклы вложенности запрещены. При удалении папки её непосредственные дети перемещаются на уровень выше.
- Изменения проходят через `BoardStore`. Он валидирует всю доску и ведёт историю отмены в памяти. Изменения из другой вкладки или с другого устройства подхватываются сразу (`store.adopt`). Между устройствами изменения сливаются по виджетам; если один виджет изменили на обоих, рядом появляется копия «— с другого устройства». Импорт JSON заменяет текущую доску после подтверждения.
- У узла может быть флаг `pinProtected`. Оболочка проверяет защиту самого узла и его предков, в том числе при переходе по прямой ссылке. Проверочные данные PIN хранятся отдельно. PIN скрывает содержимое в интерфейсе, но данные в хранилище браузера и экспортированной копии остаются открытым текстом.
- Для конвертации накоплений запрос к `api.frankfurter.dev` передаёт базовую валюту и дату. Названия счетов и остатки остаются в браузере. При изменении источника курсов проверьте сетевые разрешения расширения.

## Как добавить виджет

1. Начните с [note.js](sites/cabinet-board/dist/widgets/note.js) — это короткий рабочий пример карточки и отдельного экрана. Создайте модуль в `dist/widgets/` с именованным экспортом определения. Укажите уникальный `type`, целочисленную `version` от 1, название, описание, значок, оформление и начальный `size`.
2. Реализуйте `createData()` для начальных данных, `validate(data)` для проверки и `renderCard(ctx)` для содержимого карточки. Добавьте `renderScreen(ctx)`, если нужен отдельный экран. Оболочка уже рисует рамку компоновки, заголовок и меню карточки.
3. Импортируйте определение в `dist/widgets/index.js` и добавьте его в массив регистрации. Новый тип появится в каталоге. Для пустой доски и для уже сохранённой доски этого достаточно.
4. Сохраняйте изменения через контекст. `ctx.node` — снимок на момент отрисовки, `ctx.latest()` возвращает актуальный узел. `ctx.update(data)` заменяет объект данных виджета целиком. Например, обработчик редактирования одного поля должен сохранить соседние поля:

   ```js
   const current = ctx.latest();
   ctx.update({ ...current.data, body: input.value });
   ```

5. Для перехода в подробности используйте `ctx.open()`. Если представление запускает таймер или откладывает сохранение, верните `{ element, dispose }`, чтобы при уходе освободить ресурсы и завершить ввод. Для вывода содержимого папки используйте `ctx.children(id)`: оболочка уже скрывает сведения о заблокированных детях.
6. При несовместимом изменении `data` повысьте `version` самого типа и добавьте функцию в `migrations` под номером предыдущей версии. Проверьте загрузку старой доски и импорт её JSON. Неизвестные типы реестр сохраняет, чтобы импорт и последующий экспорт не уничтожали их данные.

## Проверка изменений

Запустите `npm test` из каталога приложения. Для правки взаимодействия дополнительно проверьте затронутый сценарий в браузере: например, для новой карточки — добавление на пустую доску и в папку, открытие деталей, ввод, возврат и перезагрузку страницы. Для изменений оболочки проверьте свободную доску мышью и узкий экран в режиме списка. Для изменений приватности откройте защищённый виджет по прямой ссылке после перезагрузки. Для изменений расширения пересоберите его и проверьте именно новую вкладку Chrome.

## 2026-11-27 — телефон и элементы управления (расширение 0.7.0)

- Панель кнопок: на телефоне (до 600 px) внизу по центру, на компьютере справа вверху. Кнопки: меню, добавить, показать все карточки, полный экран (только компьютер).
- Жесты на доске: один палец двигает поле, два — масштаб, удержание карточки — перенос. В списке удержание открывает меню карточки.
- Меню карточки: открыть, переименовать (диалог), размер и поворот (только доска), дублировать, в папку, порядок (выше/ниже в списке или на передний план), PIN, удалить. Удаление сразу, с «Отменить» в плашке.
- Меню доски разбито на разделы: Доски, Вид, Защита, Данные.
- На телефоне меню и каталог выезжают снизу, формы — у верхнего края. Сенсорные цели 40–44 px, поля ввода 16 px.
- Стили лежат в конце `dist/style.css` (блоки Controls, Touch, Phone). В `core/store.js` добавлен `shift(id, step)`. 64 теста.
